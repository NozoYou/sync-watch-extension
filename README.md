# 一起看：网页视频同步

**当前扩展版本：0.14.0**

Chrome 扩展支持 Mac 和 Windows。扩展后台维持房间 WebSocket 连接，因此切换标签页或导航到新视频时房间不会因页面卸载而断开。服务器转发少量播放控制状态和房间跳转决定，不转发视频画面或音频。

## 0.14.0 更新

## 安装扩展

OP/ED 自动识别支持 B 站番剧最低码率独立音轨，可选择浏览器本地比对或云端比对。开启后，圆盘跳过按钮只跳过当前集已匹配的片头/片尾；没有匹配的部分不提供跳过。详细使用及独立服务部署说明见 [自动 OP/ED 识别](oped-automation/README.md)。本功能尚未进行真实网站测试。

1. Chrome 打开 `chrome://extensions`，开启“开发者模式”。
2. 点击“加载已解压的扩展程序”，选择本目录。
3. 更新代码后，在扩展管理页点“一起看”的刷新按钮，再刷新视频网页。

## 启动信令服务器

服务器默认监听 `0.0.0.0:8787`。Linux 云主机上运行：

```sh
cd /home/ubuntu/sync-watch
npm install
PORT=8787 npm start
```

`ROOM_LIMIT` 可不填写，默认服务器上限为 16 人。需要降低所有房间的最高人数时，再设置 `ROOM_LIMIT`，范围为 4–16。

公网上建议配置域名和 TLS/WSS 反向代理，将 `wss://域名/ws` 转发到 `127.0.0.1:8787`。短期测试可填 `ws://公网IP:8787/ws`。防火墙需允许相应的 TCP 端口。

**更新服务器版本：**把本目录的 `server/server.js` 复制到云主机 `/home/ubuntu/sync-watch/server.js`，然后重启信令服务。使用 systemd 时运行 `sudo systemctl restart sync-watch`；直接运行时，先停止旧进程再启动新进程。`ws` 依赖没有变化，不需要重新购买云资源。

**systemd 房间人数上限：**如果 systemd 服务文件里写了 `ROOM_LIMIT=4`，请删除这项配置（默认上限 16 人），或改成 `ROOM_LIMIT=16`，然后运行 `sudo systemctl daemon-reload && sudo systemctl restart sync-watch`。

## 使用

功能菜单的“播放设置”中提供“屏蔽网页广告和可跳过的播放器广告”开关，默认开启。当前优先处理 B 站的广告卡片、推广位和播放器广告覆盖层，其次处理樱花动漫、AGE 动漫和 Omofun 的常见广告区块，最后处理 YouTube 广告覆盖层及可跳过按钮。播放器内带有广告标记的点击，以及跳向站外的播放器链接会被拦截。该功能按网页元素标记工作，不会拦截广告网络请求；无法跳过的播放器广告和视频口播推广不在当前支持范围内。未带广告标记且由网页脚本直接打开窗口的跳转仍可能漏过。不同网站会更新页面结构，选择器覆盖范围可能随之变化。

广告屏蔽下有“屏蔽推广”和“屏蔽无意义评论”两个子开关，均默认开启，关闭广告屏蔽后不可操作；再次开启广告屏蔽会默认开启两个子功能。“屏蔽推广”用于移除 B 站带小火箭标记的推荐卡片。“屏蔽无意义评论”仅检测主楼层：只要主评论正文有 @ 用户就会删除完整容器，不论是否还有文字、图片或其他留言；删除外层 `bili-comment-thread-renderer`，包括该楼层的回复和分隔区域。楼中楼回复不参与规则判断，其 @ 用户行为不会触发删除。不含 @ 用户的主评论会保留。关闭评论过滤或广告屏蔽后停止删除新评论，已删除的内容需刷新页面重新加载。评论过滤设置只保存在本机，无需房主授权，也不影响其他成员。

评论判断逻辑独立放在 `controller/player/comment-filter.js` 的 `classifyComment` 函数中，输入保留评论原文、提及用户和媒体信息，方便后续替换为 API 或小模型判断。当前只使用本地规则，不发送评论内容到外部服务。

B 站推荐卡片的“广告”标记只在文字恰好为“广告”时命中；频道标记文字恰好为“课堂”的推荐卡片也会作为广告移除。两类卡片均删除完整容器，页面排版由 B 站自身处理，不会仅隐藏文字或保留空白占位。

1. 房主打开视频网页，点扩展里的“创建房间”。其他人打开对应视频页，输入同一房间码并加入。
2. 房主在已有房间时切换到含新视频的标签页，或跳转到新视频页面；页面检测到视频后会询问是否分享。
3. 每位成员可在主界面设置房间显示名称，名称会同步显示给所有人。新成员的“播放 / 暂停”和“进度条跳转”权限默认关闭，避免本地自动播放或观看记录意外控制全房间；即使房主授予这些权限，成员自动播放和页面脚本产生的控制事件也不会转发，只有播放器附近的实际鼠标 / 触屏操作或播放快捷键会生效。房主可在“成员权限”中按名称或成员 ID 搜索、批量应用权限模板，或逐人授权。自动跟随与跟随提示属于权限 0：每位成员都可在房间主页面自主设置，无需房主授权；两项默认开启。
4. 房间会保留最近 15 条视频分享记录。最近 3 条直接显示标题和链接，更早的记录折叠显示标题；点击标题展开链接，也可用每条记录旁的按钮在新标签页打开。
5. 房主和已获授权的成员可以分别选择是否在自己跟随的新视频就绪后自动暂停；房主设置暂停 3 秒、5 秒、10 秒或直到有人点击播放。自动暂停会等待所有选择启用此功能的跟随成员就绪，再在这些成员的视频上执行。
6. 房主和已获授权的成员可以分别选择是否让自己的卡顿触发全房间暂停。房主设置卡顿等待时间为 3 秒或 5 秒（默认 5 秒）；只有启用此功能的成员连续卡顿达到设定时间后，才会暂停正在跟随的房间成员，缓冲恢复后再继续。
7. 每位成员可在房间主页面分别控制是否自动跟随新视频，以及是否显示“房主分享了新视频，是否跟随？”弹窗。首次收到该弹窗时可选择是否继续显示后续提醒；两项均可在主页面随时修改。关闭提醒不影响自动跟随开关。
8. 成员可在房间内通过右上角的小箭头按钮，把任意普通网页当前页推荐给房主。房主在“成员推荐”中查看推荐者、标题和域名，手动选择是否在新标签页打开；推荐不会自动跳转或分享给全房间。每位成员 15 秒最多推荐一次，每个房间最多保留 20 条待处理推荐。
9. 当前参与同步的标签页标题会自动加上 `[一起看]` 前缀。扩展弹窗中的“修改房间标签页图标”开关默认关闭，打开后会使用一起看的紫色播放图标。
10. 房间卡片会显示每位成员的跟随选择。成员关闭视频标签页不会退出房间；每个人都可以在扩展的“我的标签页”中自行开启或关闭“重开相同视频页时自动重新连接”（默认关闭，无需房主批准），也可以手动重新注入同步脚本。在调试区中，房主仍可查看并刷新成员的注入状态。
11. 房间卡片会显示当前视频标题、播放/暂停状态和进度。进度按最近一次房间播放状态实时估算。
12. 主机可展开独立的“调试区：注入状态与重新注入”，查看成员脚本心跳、视频检测和播放器监听状态，并对成员或主机自己的标签页重新注入脚本。重新注入不退出房间，也不刷新网页。使用远程成员刷新需要更新信令服务器并重启服务。

Chrome 扩展会在可匹配的网页 iframe 中查找 HTML5 `<video>`。DRM、canvas 播放器、浏览器禁止注入的沙盒 iframe 或非标准播放机制仍可能无法控制。所有人需要各自能访问该视频。

## 服务器和隐私

- 创建房间时房主可输入 4 至 16 的任意人数，默认 4 人。服务器的 `ROOM_LIMIT` 是所有房间的最高上限；不设置时默认为 16。房间选择人数超过服务器上限时会按服务器上限创建。
- 播放、暂停、拖动进度、倍速等控制指令以及跳转选择会经由房间服务器传递；视频内容不经过服务器。
- 房间连接由 Chrome 扩展后台维持。请勿在 Chrome 扩展管理页点“移除”来结束房间；要退出请在扩展中点“离开”。
- 公开使用时请配置 WSS，并只把房间码分享给参与者。
