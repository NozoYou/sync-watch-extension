# 一起看（Sync Watch）

当前版本：**0.14.0**。Chrome 扩展通过 WebSocket 房间同步网页视频的播放控制。视频与音频由每位用户直接从视频网站获取；房间服务器只转发控制消息、成员状态和分享记录。

## 项目组成

| 路径 | 作用 |
| --- | --- |
| `manifest.json`、`background.js`、`content.js`、`popup.*` | 扩展入口、播放器绑定、房间连接和设置 |
| `controller/` | 网页圆盘、进度环、广告与评论过滤 |
| `server/` | WebSocket 房间信令服务，默认端口 8787 |
| `oped-automation/` | 多站点连续剧集 OP/ED 音频识别与独立云端服务 |
| `oped-detector/` | Python 离线检测与人工审核工具 |

## 安装扩展

1. Chrome 打开 `chrome://extensions`，开启开发者模式。
2. 点击“加载已解压的扩展程序”，选择本项目根目录。
3. 在扩展“连接设置”填写房间服务器地址。所有参与者填写相同地址。
4. 更新文件后，在扩展管理页重新加载扩展，并刷新已打开的视频网页。

支持 macOS 和 Windows 上的 Chrome。页面脚本寻找网页及 iframe 中的 HTML5 `<video>`；DRM、受限 iframe、canvas 和非标准播放器可能无法绑定。直播不参与进度同步。

## 部署房间服务器

需要 Node.js 18 或更新版本。源码位于 `server/`，唯一 npm 依赖是 `ws`：

```sh
cd server
npm install
PORT=8787 npm start
```

本机连接地址为 `ws://127.0.0.1:8787/ws`。远程部署建议通过 HTTPS 反向代理提供 `wss://你的域名/ws`；示例见 `server/Caddyfile.example`。默认每房间上限 16 人，可用环境变量 `ROOM_LIMIT=4` 至 `16` 降低上限。房主创建时可另选本房间人数，界面默认 4 人。

长期运行可用 systemd 托管 `npm start`。更新服务器文件后重启对应服务；服务名若为 `sync-watch`，运行 `sudo systemctl restart sync-watch`。房间状态保存在进程内存中，服务器重启后不保留房间。

## 功能

### 房间与同步

- 房主创建房间、分享视频页面；成员凭房间码加入，可自行选择自动跟随或接收跟随提示。分享历史最多保留 15 条。
- 同步播放、暂停、进度跳转和倍速。成员的播放/暂停与拖动权限默认关闭；房主可逐人授权或批量套用权限。
- 成员可推荐网页给房主，由房主决定是否打开。每位成员 15 秒最多推荐一次，每房间最多保留 20 条待处理推荐。
- 房主可设置切集后暂停、成员就绪后自动暂停、卡顿后暂停全房间，以及停用自动进度校准。手动拖动仍可同步。
- 显示成员和与服务器的往返延迟。扩展后台维持 WebSocket，断线后尝试重连；提供播放器重新绑定和脚本重新注入入口。

### 网页圆盘与记录

- 默认启用网页圆盘：创建、加入、离开、保存进度、重新绑定、跳过，以及查看房间分享历史和本地历史。目前只有经典扇区款式。
- 圆盘可拖动、贴左右侧收起、调整至 120–240 px，并在全屏显示；外圈显示播放进度，可选播放时旋转装饰。设置中可关闭圆盘、切换浅色/深色/跟随系统主题、重置位置。
- 本地保存的进度最多 15 条，存于 Chrome 扩展本地存储；可打开记录恢复进度。它与房间分享历史分开保存。
- 未启用 OP/ED 识别时，圆盘跳过按钮按设置时长快进，默认 85 秒。

### 连续剧集 OP/ED

- 在“播放设置 → OP/ED 音频识别”选择本地浏览器或云端服务器。支持可读取分集目录及独立音轨的 B 站番剧、UP 主合集和至少三 P 的普通视频；同时接入 OmoFun、樱花动漫的默认公开播放源，以及 AGE 可直接解析的播放源；AGE 使用 WASM 加密的线路暂不能自动取得相邻集媒体。单个独立视频不进行连续剧集识别。
- 读取当前集和相邻两集的音频比对重复片段；B 站优先最低码率独立音轨，其他站点 HLS 仅取首尾约五分钟分段；先处理当前集，再分批处理整季。至少需要三集可访问的正片。
- 已识别区间可高亮在 B 站、ArtPlayer、DPlayer、Video.js 的网页进度条上。点击跳过或房主开启房间自动跳过时，定位到 OP/ED 结束前 3 秒；没有匹配的集不提供该跳过。
- 本地结果保存在 Chrome 扩展专用文件系统的 `oped-records.json`。云端模式只上传音频特征，不上传音频文件或视频流；可另存云端记录。
- 配置检测服务地址后，先按剧集 ID 或 BV＋P 号读取云端已识别时间点；命中时直接跳过音轨下载与分析。新结果由配置了地址和密钥的客户端写入云端，其他用户可读取。
- 可在功能菜单点击“重新识别当前系列并上报”，重新处理当前集及后续批次。普通用户无需服务器密钥；同一视频在 180 天内获得 5 个不同网络来源的一致上报后，服务器独立下载音轨重新识别，验证一致才更新正式云端时间点。服务器需安装 ffmpeg。
- 当前下载完整的低码率音轨，每集上限 64 MB、1 小时；尚未按字节范围只取首尾。配置及数据格式见 [OP/ED 文档](oped-automation/README.md)。

### 页面过滤

- 广告过滤默认开启：以 B 站广告和推广卡片为主，也处理 AGE、樱花动漫、Omofun、YouTube 等网站的部分广告元素及可跳过广告。对 AGE、樱花、OmoFun 及其播放器 iframe 共用弹窗、播放点击诱导外链与遮罩拦截模板，受“屏蔽广告”开关控制。任意脚本直接修改当前页面地址和混入正片的广告不能保证拦截。它不处理视频口播。
- “屏蔽推广”识别 B 站特定小火箭标记。“屏蔽无意义评论”当前只检查 B 站主楼：正文含 `@` 用户时删除整个楼层，楼中楼回复不单独判断。规则可能误删正常评论；关闭后需刷新网页才能恢复已删除内容。

## 可选：部署 OP/ED 云端比对服务

它与房间服务器分开运行，需要 Node.js 18 或更新版本，以及至少 24 字符的 `OPED_TOKEN`。保持 `oped-automation/server/` 和 `oped-automation/extension/audio-core.js` 的相对路径：

```sh
export OPED_TOKEN='替换为至少24字符的随机密钥'
node oped-automation/server/server.js
```

服务默认监听 `127.0.0.1:8788`，可通过 `OPED_HOST`、`OPED_PORT` 修改。远程使用时将 HTTPS 的 `/detect` 和 `/records` 代理到该端口，在扩展“云端配置”填写地址和相同密钥。云端记录默认写入 `oped-automation/server/data/oped-records.json`，可用 `OPED_RECORD_FILE` 指定路径。详见 [云端服务文档](oped-automation/server/README.md)。

## 当前限制与待开发

- 房主离开后的房间归属、加入不存在房间码的处理，以及成员身份认证需要完善。公开部署应使用 WSS 并限制服务访问。
- 网站播放器重建、跨域 iframe、网络抖动和全屏交互仍需逐站实测；通用同步只适用于扩展可访问的 HTML5 视频。
- OP/ED 依赖公开目录和可解析的媒体源；重复前情或插曲可能误判。AGE 部分加密线路不支持，HLS 直播、SAMPLE-AES/DRM、字节范围播放列表不支持。
- 广告和评论过滤依赖页面结构；B 站首屏广告删除后的骨架补位仍需验证。尚未实现 AI 账号或低质量评论的语义识别。

0.14.0 新增 UP 主合集与多 P 的 OP/ED 识别入口；合集接口目录缺失时，从 `video-pod` 列表项的 `data-key` 读取 BV 号。更新记录见 [发布说明](RELEASE_NOTES.md)。

多站点 OP/ED 云端记录以 `web:<域名>:<视频ID>:<线路>:<集数>` 区分来源，系列和每集都保存 `sourceDomain`。例如同一作品在 `omofun.in` 与 `yhdm.one` 的结果独立保存，不按标题共享；原 B 站 ID 与已有记录继续兼容。
